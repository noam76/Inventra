# Règles de Développement

## Règles Générales

1. Développer une seule fonctionnalité à la fois.

2. Attendre systématiquement la validation explicite avant de passer à la fonctionnalité suivante.

3. Ne jamais anticiper les étapes futures sans validation.

4. Respecter strictement l'architecture du projet.

5. Respecter la séparation des responsabilités entre les fichiers.

---

## Gestion du Code

6. Les commentaires dans le code doivent être rédigés en anglais.

7. Ne jamais réécrire un fichier complet si une modification partielle suffit.

8. Fournir uniquement le code à ajouter, modifier ou supprimer.

9. Toujours indiquer l'emplacement exact du code concerné.

10. Favoriser les modifications minimales.

---

## Gestion des Réponses

11. Fournir des explications courtes et directes.

12. Éviter les réponses inutiles ou hors sujet.

13. Respecter les limites de tokens.

14. Découper les développements importants en plusieurs parties.

15. Ne jamais générer plus de 50 lignes de nouveau code en une seule fois.

---

## Architecture

16. Utiliser les fichiers JSON prévus par l'architecture.

17. Respecter la structure des dossiers du projet.

18. Isoler chaque fonctionnalité dans son module dédié.

19. Éviter les dépendances inutiles entre modules.

---

## Validation

20. Vérifier la cohérence avec la documentation avant chaque proposition.

21. Vérifier l'impact sur les autres modules avant toute modification.

22. Maintenir la compatibilité avec les versions précédentes lorsque cela est possible.
